# 媒体运行时迭代与性能基线（2026-10-13）

本轮按独立提交交付统一媒体调度、导出任务隔离和性能基准。工作基于已提交的
主分支建立独立工作区；原工作区其他未提交的架构、协作和场景改动未打包进来。
上轮音频与字幕修复先作为基础提交固定。

## 验证

- 生产构建通过。
- 234 项 SDK 测试、4 项基准比较器测试、10 项浏览器测试通过；浏览器测试没有跳过。
- 浏览器验证实际 MP4 音频、代理抢占、暂停回跳、导出版本隔离、3D 实时编辑隔离、
  取消/失败清理、独立输出删除，以及原有预览和 MCP 行为。
- 专项故障注入验证：存储耗尽不会降级为整段内存导出；解码器排空保留资源名额；
  流解码出错不会被当成正常文件结束；传输失败关闭克隆帧并释放渲染队列名额。

## 原生 GPU 标准基线

Apple M3 Max、64 GiB、Chromium 149.0.7827.55，
Metal / Apple GPU。完整环境、素材哈希、构建哈希、原始样本和资源读数在
[结果 JSON](media-runtime-2026-10-13.json)。每个重复指标一次预热加五次测量。

| 工作负载 | 指标 | 本轮观测 |
| --- | --- | ---: |
| 4K AVC，2 秒 / 12fps | 精确随机取帧 p95 | 54.87 ms |
| 同一 4K 素材 | 新建代理 p95 | 182.46 ms |
| 8 轨 × 200 片段、4 个 1080p 源 | 跳转到源帧就绪且渲染 Worker 确认 p95 | 54.45 ms |
| 同一多轨项目 | 100 次时间线求值 p95 | 0.38 ms |
| 同一多轨项目的 2 秒范围 | 完整导出 p95 | 1900.33 ms |
| 10 分钟单声道 WAV | 1 秒随机 PCM 窗口读取 p95 | 0.45 ms |
| 4,096 实例、8 动画组 | 姿态与渲染提交 p95 | 7.32 ms |
| 同一 3D 场景，2 秒 | 完整导出 p95 | 207.08 ms |

这里的时间是本次构建的基线，不是相对旧版本的加速比例。五次样本的 p95 接近
最大值，不能作为生产服务承诺。Worker 确认不是操作系统屏幕呈现；JS 堆与帧缓存
估计不等于浏览器总内存/总显存。素材是固定合成样本，不代表多小时长 GOP、HDR、
VFR 或几十 GB 原始文件的容量边界。

## 重复运行的告警

两次相同构建、相同环境的快速基准，比较器按默认 30% 且超过 5ms 的阈值
报告两项退化告警：代理生成 p95 约 184 → 378ms，多轨导出 p95 约 1.07 → 1.56s。
代理中位数约 182 → 184ms，多轨导出中位数约 1.03 → 1.07s；尾部尖峰导致告警。
原始比较保留在结果 JSON 的 repeatabilityCheck，未通过放宽阈值使其转绿。

两次代码/构建相同，这些结果说明短样本在当前桌面负载下存在波动，尚不能归因
为代码变更造成的退化。后续应增加重复样本、控制其他 GPU/编码负载，并增加
解码、编码和文件写入分段计时后再确定稳定的 CI 性能门槛。

当前最值得继续细分的是多轨视频导出链路，其 2 秒范围的导出耗时显著高于本组
合成 3D 用例；这是后续定位方向，不是对剪映导出速度的比较结论。

复跑方式与边界见 [设计说明](../design/media-runtime.md)。浏览器关闭仍会终止任务；
本轮没有实现独立桌面进程或跨重启续导。成功导出的临时文件需在下载完成后显式清理。
