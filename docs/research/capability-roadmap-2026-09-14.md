**Velocut 能力扩展调研：剪映、ChatCut 与可落地的集成方向**

调研日期：2026-09-14。Velocut 基线：已发布的 0.0.1 / 提交 `11ecf5b`。依据为产品官方页面、官方文档、公开插件仓库和本地源码；没有登录竞品进行实测。竞品功能描述代表公开声明，以下优先级、实现方式和复杂度是针对 Velocut 的工程判断，不是竞品内部架构结论。

**建议优先形成两个完整流程：口播素材到可交付短片，以及产品模型到可编辑的三维宣传片。** 前者扩大日常用途，后者复用现有 Director、SceneSpec、CodeAct 和 GLB 投入。先完善已有能力的连接，再增加模型和高级特效。

**竞品给出的方向**

剪映官网列出了文字剪口播、素材智能搜索、音频降噪／人声分离／响度统一，以及蒙版、调色、多机位和多时间线。这些能力共同解决素材处理、剪辑、声音和交付问题，不能只拆成若干生成按钮来模仿。[剪映官网](https://www.capcut.cn/)

ChatCut 的文字稿面板把词语操作映射到时间线切割和空隙闭合；口播工作流还组合了挑选拍摄版本、删重复、缩短停顿、字幕和 B-roll。值得借鉴的是“分析结果成为可编辑对象，AI 和人使用同一操作”。[文字稿与字幕](https://chatcut.io/docs/transcript-and-captions)、[口播工作流](https://chatcut.io/docs/talking-head-edit)

ChatCut 的 Design Styles 包含字体、颜色、Logo、参考图片和文字规则；其导出队列提供状态、取消和重试。这说明创作一致性与长任务管理同样属于产品能力。[风格复用](https://chatcut.io/docs/design-styles)、[导出队列](https://chatcut.io/docs/export-history)

ChatCut 公开提供 Agent Plugin 仓库并连接自己的托管 MCP 服务。这不能证明其完整编辑器或后端可以作为开源 SDK 嵌入 Velocut。本次借鉴工作流和接口边界，不依赖其私有实现。[公开插件仓库](https://github.com/ChatCut-Inc/agent-plugin)

**Velocut 已有基础与实际缺口**

| 领域 | 已有基础 | 优先补充 |
|---|---|---|
| Agent | MCP、CodeAct、引用、观察、版本检查、历史；场景编辑很完整 | 通用本地媒体导入、转写、MG、视频导出和任务查询的 MCP 覆盖；明确宿主能力发现 |
| 字幕 | Whisper 转写；定时文本片段；可编辑样式 | 持久化词级文字稿、说话人、字幕与源素材时间映射、SRT/VTT 导入导出 |
| 时间线 | 多轨、分割、裁剪、恒定变速、多选、批量命令 | 关闭空隙、插入／提取、跨轨同步编辑、关联音视频、编辑计划预检 |
| 声音 | PCM 解码、混音、音量关键帧、预览倍速、可选 TTS | 变速片段的预览／导出音频、保音调变速、响度处理、自动压低 BGM |
| 视觉 | 调色、模糊、锐化、色键、发光、着色器、声明式 MG | 几何／路径蒙版、主体跟踪、自动重构图、统一品牌模板 |
| 生成 | 可插拔 VideoGenerator、TTS、上传接口 | 独立服务商能力描述、持久任务队列、结果归档；当前 MCP 未开放相关云能力 |
| 三维 | SceneSpec、角色、灯光、镜头、组件、批量布局、GLB | 分镜板、镜头节奏编辑、产品拆解动画模板、透明渲染和条件图输出 |
| 交付 | 浏览器 MP4 编码／封装、静态 GLB、CLI 分发 | 项目打包／重连、音频和字幕单独导出、导出队列、时间线交换 |
| 协作 | Yjs、IndexedDB/OPFS、同源标签页同步 | 审片链接、时间码评论、远程素材同步与权限；不能把当前能力当作完整多人云协作 |

源码证据：

- [`server.mjs`](../../web/packages/mcp/src/server.mjs) 和 [`host.ts`](../../web/packages/runtime/src/host.ts)：MCP 有 GLB 文件进出、场景编辑和时间线命令，但没有通用媒体文件导入／最终视频导出工具；脚本中的 TTS、motionClip、videoGen 等仍被该宿主禁用。
- [`transcribe.ts`](../../web/packages/render-sdk/src/transcribe.ts)：当前转写返回段级文本；音频按窗口解码但仍汇总成整段 PCM 送入转写，长素材内存问题需要单独处理。
- [`caption.ts`](../../web/apps/editor/src/services/caption.ts)：当前从资产转写到字幕片段，还没有完整的源词时间到时间线实例的映射层。
- [`Toolbar.tsx`](../../web/apps/editor/src/ui/Toolbar.tsx)：导出音频计划排除了 `clip.speed !== 1` 的片段。这个功能缺口应先于复杂的智能音频包装解决。
- [`effects.ts`](../../web/packages/render-sdk/src/effects.ts)：已有特效注册机制及色键，新增主体分割不应被描述为“第一次支持抠像”；应区分绿幕色键与 AI 主体分割。
- [`videogen.ts`](../../web/packages/render-sdk/src/videogen.ts)、[`collab-sdk`](../../web/packages/collab-sdk/src/index.ts)：分别提供生成供应商接口和本地同步基础。

**候选能力与排序**

复杂度是相对于现有代码的 MVP 工作量：低为复用现有接口和界面；中为新增稳定数据模型／服务及端到端链路；高为跨渲染、时间线或原生运行环境的大型改动。商业级质量通常还需要更长的兼容性验证。

| 优先级 | 能力 | 用户能完成什么 | 建议实现边界 | MVP 复杂度 |
|---|---|---|---|---|
| P0 | Codex 完整剪辑链路 | 读取本地素材，分析、剪辑、加字幕并导出成片 | 扩展共享 runtime；MCP 仅做代理；长任务返回 jobId | 中 |
| P0 | 文字稿剪辑／智能口播粗剪 | 删除口头语、重复句、停顿；按主题重组访谈 | 词级 ASR/VAD + 稳定文字稿模型 + 原生时间线事务 | 中高 |
| P0 | 字幕工作台 | 校正、分句、合并、逐词强调、双语字幕、SRT/VTT | 复用文本渲染，新增字幕程序与源素材关联 | 中 |
| P0 | 声音与交付补齐 | 变速仍有声音、对白更清楚、BGM 避让人声 | 共用音频处理计划，保持预览／导出一致；重处理可选本地服务 | 中高 |
| P1 | 本地素材语义搜索 | 找出“讲到退款政策”的句子或“出现产品特写”的镜头 | 转写／镜头／关键帧索引 + 检索；返回带时间码的证据 | 中 |
| P1 | 长视频转短视频／自动重构图 | 生成几个候选精彩片段和横竖屏版本 | 检索 + 编辑计划 + 人脸／主体检测 + 平滑裁切关键帧 | 中高 |
| P1 | 品牌包与可编辑模板 | 同一 Logo、字体、颜色产出多条广告或教学视频 | 参数化 JSON 配方，生成普通可编辑文本／MG／3D 对象 | 低中 |
| P1 | 分镜板与三维产品短片 | 调整镜头顺序、时长、运动；生成产品环绕和拆解动画 | 扩展现有 SceneSpec、shots、组件和 timeline，不重新建一个 DCC | 中 |
| P1 | 开放交付与项目归档 | 携带素材搬家、在其他 NLE 中继续精修 | 先完整项目包与基础 XML/OTIO，再评估剪映草稿适配 | 中高 |
| P1 | 统一生成与渲染队列 | 任务可取消、失败可重试，生成结果自动入库 | Provider + Job + Artifact；先复用现有生成接口 | 中 |
| P2 | AI 主体抠像／跟踪蒙版 | 人像换背景、背景局部模糊、跟随目标的标注 | 原生蒙版表示与渲染 + 可替换分割模型；评估帧间稳定性 | 中高 |
| P2 | 多时间线／复合片段／多机位 | 管理多个版本、嵌套段落、音频同步切机位 | 需要编辑模型与求值器扩展，后续专项设计 | 高 |
| P2 | 录屏／摄像头／旁白录制 | 在产品内直接获得教程、演示素材 | 用户触发设备授权，录制结果成为普通素材 | 低中 |
| P2 | 审片与远程协作 | 时间码评论、分享审片、跨设备团队编辑 | 审片先行；完整权限、素材同步、冲突处理后续 | 中高 |

**第一条重点流程：口播剪辑**

建议交付目标：“导入一段访谈，找出三个主题片段，删掉指定停顿和重复句，生成一条 60 秒短片，校正字幕后导出视频与 SRT。”

真正需要的基础数据是“资产中的词语／说话人／时间码”和“这些词语在当前时间线的实例”，而不是一串字幕字符串。一次素材可能被放入多个 clip，经过裁剪、移动、变速后，仍应指向正确的源词。ASR 结果和静音候选可缓存；用户接受的剪辑则通过 `expectedRevision` 和时间线事务提交。

第一版先支持人工确认的句段删除、停顿缩短和关键词检索，再做自动重复拍摄版本选择与完整语义重组。VAD 只能判定有无语音，不能单独决定哪些内容是废话。对齐误差、中文断词、呼吸声和嘴型跳切都要进入验收样例。

可以继续扩展当前 Transformers.js 路径，其公开 API 文档已有词级时间戳用法；需要在项目锁定的版本、模型和中英文素材上验证。长文件或更重的批处理可通过可选本地服务使用 faster-whisper，它提供词级时间戳及 VAD 集成。[Transformers.js 时间戳示例](https://huggingface.co/docs/transformers.js/v2.17.2/en/api/pipelines)、[faster-whisper](https://github.com/SYSTRAN/faster-whisper)

**第二条重点流程：三维产品宣传片**

建议交付目标：“导入 GLB，选择品牌样式，生成三个可编辑镜头，加入功能标注和旁白，导出宣传视频及镜头清单。”

先建设分镜卡片、镜头路径模板、场景构图检查和参数化产品拆解。复用现有三维对象／动画能力，用户仍能修改每个对象和镜头。后续再增加透明画面、深度图、法线图和对象遮罩，作为合成素材或支持这些输入的生成服务的条件图。不能假设每个图生视频 API 都接受这些通道。

品牌包不仅是提示词：保存颜色、字体、Logo、字幕样式、标题排版、场景灯光和动画节奏参数；模板实例保留参数与生成对象之间的关系。已有作品是否跟随品牌更新，应该是明确操作。

**与剪映等编辑器的连接**

值得做“Velocut 粗剪／生成 → 其他编辑器精修”。ChatCut 官方文档提供桌面端可编辑剪映／CapCut 草稿交付，也提供面向 Premiere／DaVinci 的 FCP7 XMEML；两条路线都存在不支持的对象或属性。[剪映／CapCut 交付](https://chatcut.io/docs/export-capcut-jianying)、[XML 交付](https://chatcut.io/docs/export-xml)

建议从基础剪辑点、轨道、素材引用和简单变换开始，实现清晰的兼容性报告。Velocut 的三维场景、复杂 MG 和特殊效果可以渲染为素材替代，同时保留原项目供继续编辑。OPFS 地址无法直接交给其他编辑器，需要打包真实素材并重写引用。

OTIO 适合交换剪辑信息，核心数据引用外部媒体，不等于已经把素材一起导出了；适配器也要逐项验证。浏览器可先输出经过校验的中间结构，完整 OTIO/Python 适配可以放在可选本地服务中。[OTIO 官方文档](https://opentimelineio.readthedocs.io/en/latest/)

剪映草稿适配值得做验证性原型，但本次没有查到可据以承诺长期兼容的官方开放草稿写入契约。应明确支持的应用版本，不把第三方草稿脚本作为核心项目格式，也不承诺完整往返。ChatCut 的产品功能不能直接视为 Velocut 获得了对应 API 或授权。

**可复用的组件**

| 组件 | 用途 | 接入建议与约束 |
|---|---|---|
| 现有 Transformers.js + Whisper | 浏览器转写、后续词级文字稿 | 先复用已有依赖，按需下载模型；长片改为有状态分块处理 |
| [Silero VAD](https://github.com/snakers4/silero-vad) | 语音活动与停顿候选 | 仓库公开标注 MIT，提供 ONNX 使用路径；接入浏览器仍需实时性能验证 |
| [faster-whisper](https://github.com/SYSTRAN/faster-whisper) | 可选本地批量转写 | Python/CTranslate2 路径，适合作为可选服务，不放进默认浏览器依赖 |
| [MediaPipe Tasks Vision](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/tasks/web/vision/README.md) | 检测、分割等端侧视觉能力 | 可评估自动裁切／人像蒙版；视频帧间跟踪、平滑、质量回退仍需自己实现 |
| [Mediabunny](https://mediabunny.dev/guide/supported-formats-and-codecs) | 媒体读写、封装与格式能力检查 | 作为媒体层迁移候选；支持某种容器不代表浏览器一定能解码／编码其中的格式 |
| [FFmpeg](https://ffmpeg.org/ffmpeg-filters.html) | 响度处理、BGM 避让、变速、代理转码、特定导出 | 优先可选本地工作进程；浏览器预览仍需要一致的处理计划／烘焙缓存 |
| [OpenTimelineIO](https://github.com/AcademySoftwareFoundation/OpenTimelineIO) | 时间线交换与适配器生态 | 不负责渲染，也不保证所有目标软件的特效可迁移 |

现有 `mp4-muxer` 的上游已宣布由 Mediabunny 接替，因此媒体封装升级有实际维护理由，但应作为兼容性迁移处理，不能一次替换整个解码／渲染链路。[上游迁移指南](https://github.com/Vanilagy/mp4-muxer/blob/main/MIGRATION-GUIDE.md)

选型时记录具体版本、模型权重许可与分发方式。Mediabunny 标注 MPL-2.0；FFmpeg 的许可条件随构建选项和链接库变化，不能笼统当作全部 MIT 组件处理。采用前按实际组合核验。[Mediabunny 官方页面](https://mediabunny.dev/api/ALL_FORMATS)、[FFmpeg 官方许可说明](https://ffmpeg.org/legal.html)

**建议的架构组织**

先在现有模块中落地，稳定后再决定独立 npm 包，不为每个按钮新增包：

| 层 | 建议职责 |
|---|---|
| protocol / core-ts | 文字稿映射所需标识、时间线编辑计划、轨道同步规则与事务 |
| render-sdk | 音频处理计划、字幕／蒙版渲染、媒体能力检测、可复现导出 |
| runtime | 素材分析索引、任务生命周期、项目级资源、导入导出协调、冲突校验 |
| scene-sdk | 分镜、镜头和场景模板、三维输出通道 |
| mcp / 插件 | 暴露同一套能力；读取任务与结果；不重复实现业务逻辑 |
| 可选 Provider / 本地服务 | ASR、分割、生成、FFmpeg 等外部执行能力 |

建议新增的接口方向（以下是提案，尚未实现）：`getCapabilities`、`importMedia`、`analyzeMedia`、`queryMedia`、`editTimeline`、`render.submit/get/cancel`。任务返回可查询的 jobId；耗时分析与生成不要绑在一次脚本 RPC 的生命周期中。任务产物使用项目资源 ID，记录输入素材哈希、模型／参数及结果文件；切换项目、取消或重试时不重复写入时间线。

默认安装保持浏览器 + Node 的轻量路径。重模型、原生转码和商业生成 API 都按需启用。已有 Codex 模型负责理解与规划，转写／视觉／视频生成的计算能力另行提供；不能把 Codex 订阅等同于所有外部生成服务的额度。不要直接复制竞品素材库或假设字体、音乐、模板授权可转移。

**建议落地顺序与验收**

1. **完成可交付剪辑链路。** 补通用导入、视频／字幕导出任务、MCP 能力发现；解决变速音频；建立源文字稿映射和基础 gap/ripple 操作。验收：用户和 Agent 都能从同一素材产出有声、同步、有字幕的成片；失败不留下半个编辑计划。
2. **完成口播与品牌流程。** 文字稿剪辑、停顿处理、素材关键词搜索、字幕样式、品牌配方和候选短片。验收：所有自动决定都能定位回源素材，并可修改／撤销；至少覆盖中文、英文、长停顿、重复拍摄和重排后的字幕。
3. **强化三维差异和外部交付。** 分镜板、产品动画模板、透明素材、基础 XML/OTIO；最后验证剪映草稿、自动重构图和高级分割。验收：目标 NLE 中的剪辑时长、帧率、音画对齐与素材重连正确；未支持内容明确列出。

首轮暂缓：自研基础视频模型、完整数字人／口型系统、完整专业调色系统、无损兼容所有剪映草稿版本，以及大规模素材商城。这些能力可以作为后续服务／适配器引入，当前投入产出不如打通剪辑闭环。
