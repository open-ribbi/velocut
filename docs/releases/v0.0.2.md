# Velocut 0.0.2

Velocut 0.0.2 brings automatic local Studio startup from Codex, configurable media
models through YAML/JSON, timeline-native video generation, and more precise atomic
editing tools. It also introduces the lime mascot holding editing scissors.

## Install without source code

Requires **Node.js 22.6+**, npm for the Git installation route, and Chrome/Edge
with WebGPU/WebCodecs. The portable download does not require npm.

In Codex, add the plugin marketplace with source **`open-ribbi/velocut`**, Git ref
**`v0.0.2`**, and optional sparse paths `.agents/plugins` and `plugins/velocut`.
Install Velocut, start a new task, and ask Codex to open it. The pinned MCP package
installs the matching CLI and starts or reuses Studio on the first connection.
No source checkout, build command or manually maintained terminal is needed.

Alternatively, download **velocut-standalone.zip** or **velocut-standalone.tar.gz**,
extract it and add the `velocut-0.0.2` directory as a local Codex marketplace.
The bundled plugin automatically starts the bundled Studio. Manual startup remains:

```sh
node start-studio.mjs
```

Standalone npm usage:

```sh
npx @velocut/cli@0.0.2 studio
```

## New in this release

- **Automatic Studio startup.** Reuse compatible local services, keep Studio alive
  across Codex chats, and stop managed Studio after ten idle minutes without active
  requests or editor heartbeats. Port/version conflicts do not silently change the
  project's browser origin or terminate another application.
- **Declarative media models.** Import/export YAML or JSON, validate nested parameters,
  preview requests locally, and configure a service Base URL and token. Codex can
  author definitions through `velocut_models`; tokens stay outside tool responses.
  Bundled Task API, Ark and MiniMax recipes use the same executor as custom models.
- **Timeline-native video generation.** Draw a generation range, retain multiple
  candidates, preview results and adopt one into the timeline. Durable receipts
  resume tracking after reload; uncertain submissions are never automatically
  re-submitted. References upload only on an authorized submission.
- **Atomic Agent editing.** Capability/schema discovery, bounded queries, dependent
  transactions, media import/probe jobs and complete clip duplication.
- **More precise 3D authoring.** Shared geometry instances/materials/animation curves,
  per-instance timing, spatial queries, anchors, surface attachments, pose bindings,
  local geometry repair previews, collision shapes and physical joints.
- **Memory and playback improvements.** Shared resources and history deduplication,
  incremental instance updates, removal of fixed scene byte/instance ceilings, and
  recovery from stalled preview audio clocks.
- **Branding.** New mascot/scissors icon and bundled plugin images; default starter
  cards are hidden to avoid the desktop host's broken background image.

## Packages

Eight coordinated npm packages at **0.0.2**:
`@velocut/provider-sdk`, `@velocut/protocol`, `@velocut/core-ts`,
`@velocut/render-sdk`, `@velocut/scene-sdk`, `@velocut/runtime`,
`@velocut/cli`, and `@velocut/mcp`.

Vendor-specific provider packages were removed before their public release.
Existing render-sdk entry points delegate to the shared declarative executor.

## Upgrade notes

- Keep the same browser profile, hostname and port to retain browser-local projects.
  Close an older manually started Studio before using automatic startup at that port.
- Update/install the plugin and start a new Codex task to load its current tools.
- Documents migrate forward to format **5**. Older editors cannot read saves written
  in this format; retain an older project copy if rollback is required.
- Video/audio generation uses the configured service account and its credits.
  Configuration validation and request preview do not call the provider.
- Declarative tokens are stored in a local plaintext configuration file with mode
  0600 on POSIX, not an OS keychain. They are not returned to Codex.
- This is a local Git/portable marketplace integration; it is not an official
  public Plugins Directory listing. Node itself and a browser are not bundled.

`manifest.json` records the source commit and package hashes.
`distribution-verification.json` records independent consumer checks, including a
fresh npm cache, automatic startup, browser pairing, worker rendering and SDK use.
`SHA256SUMS.txt` covers the package tarballs, portable archives and release metadata.
All provider tests use mock services; verification does not spend generation credits.
