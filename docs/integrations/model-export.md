# GLB model export (unreleased)

Available from the current source build. The already-published 0.0.1 release
has not been replaced. No new third-party runtime dependency is required:
export uses Three.js GLTFExporter.

## Director

Open the Director's **More tools → Export GLB…** menu. Choose the entire scene
or the selected object and its descendants, then **Download GLB**. Opening the
dialog pauses playback. The export samples the displayed scene-local time.
Whole-scene exports can include environment geometry and the authored shot
camera. Selection exports keep their ancestor transforms/world placement and
exclude unrelated geometry, environment and the shot camera.

## SDK and browser API

```ts
import { exportSceneGlb } from '@velocut/scene-sdk';
const { blob, warnings } = await exportSceneGlb(spec, {
  timeS: 0.5,
  objectIds: ['table'], // omit for the whole scene
  assetBase: '/scene-assets',
  resources, // modelBytes resolver for project-owned imported GLBs, if any
});
```

For a project use `exportSceneModel(store, options, signal?)` from
`@velocut/runtime`. The same operation is exposed as
`await window.velocut.sceneExport({ assetId, timeS, objectIds })` in Studio.
The project operation returns `{ ok, blob, assetId, revision, timeS, objectIds,
warnings }`, or `{ ok: false, message }`. `expectedRevision` can reject a stale
request before export. Exports snapshot the source document and do not change
selection, authored data, undo history or the live viewport. Concurrent later
edits do not change an export already in progress; its revision identifies the
snapshot. SDK callers can use AbortSignal to cancel before delivery.

## MCP

`velocut_export_model` accepts `sessionId`, `assetId`, absolute destination `path`,
and optional `objectIds`, `timeS`, `includeEnvironment`, `includeCamera` and
`expectedRevision`. Time defaults to 0. Export to a new `.glb` file in an existing
directory. The server commits the complete file atomically without overwriting
an existing file or following an existing destination symlink. It returns the
path, size, snapshot revision and warnings; base64 model bytes are not exposed
to the model conversation. It requires filesystem hard-link support for the
atomic commit (standard APFS/NTFS/ext4). Export never creates a document edit.

## What is preserved

- Object hierarchy, world placement, mesh geometry, materials, texture maps and UVs.
- Sampled object transforms and the visible skin/morph pose, baked into static mesh geometry.
- Point/spot/directional lights and the authored shot camera for whole scenes.
- Editable geometry generated by assemblies; the assembly recipe is not retained.

This is a **static snapshot**, not animation export. Skinning and morph weights
are baked into vertex positions/normals; rigs, morph targets and animation
clips are not retained. Procedural actions,
physics settings, assembly recipes, timeline tracks and Velocut history do not
round-trip through GLB. Ambient lighting, scene backgrounds and renderer-specific
shadows/post-processing are not encoded; imported scenes may need lighting
adjustments in another application. Director gizmos and grid helpers are absent.

The default preserves texture resolution. The SDK supports an explicit
`maxTextureSize` when a caller wants to resize textures. Exports are limited to
64 MiB and 2 million vertices to remain compatible with Velocut's importer. An empty/non-mesh selection,
invalid time/object IDs, missing project resources or exporter errors fail with
an actionable error rather than producing an incomplete download.

## Verification

`web/e2e/model-export.spec.ts` exercises hierarchy/world transforms, sampled
skin and morph geometry, embedded texture pixels, lights/camera toggles,
read-only revision behavior, compact-window downloads and MCP no-overwrite
file output. The distribution test exports and reimports using installed
package tarballs outside the source checkout.

For an independent Blender check after running the browser export tests:

```sh
blender --background --factory-startup --python-exit-code 1 \
  --python web/scripts/verify-glb-blender.py -- web/test-results
```

The helper loads the produced files into fresh Blender scenes and compares
world bounds, accounting for Blender's Z-up coordinates. Blender is optional
validation tooling, not a Velocut runtime dependency.

Validated locally with Khronos glTF Validator (zero errors/warnings on four
export fixtures) and Blender 5.2.0, including world-bound comparisons for a
posed character and a selection under rotated/non-uniformly scaled parents.
