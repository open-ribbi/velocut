# 时间线内视频生成：产品调研与 Velocut 设计建议

状态：调研与设计提案，尚未实现。调研日期：2026-09-16。

本轮将重心转回视频剪辑。资料来自产品官方文档、官方发布说明及 Velocut 当前源码；没有登录竞品执行付费生成。公开资料用于确认交互，不据此推断竞品内部 API、任务持久化或事务实现。

## 最接近目标的产品

用户描述的“在轨道上拉出一段片段，然后调用视频生成”有明确对应：**Premiere Generative Media Tool**。

Adobe 在 2026 年 7 月的公告中以 Beta 介绍该功能；9 月 9 日更新的正式桌面发布说明已将它列入 **Premiere 26.5**。不要仅依据较早公告或更新较慢的地区文档，继续把它描述为只能在 Beta 使用。[正式版本说明](https://helpx.adobe.com/premiere/desktop/whats-new/release-notes.html)

| 产品 / 功能 | 官方确认的入口与落轨方式 | 可借鉴的重点 |
| --- | --- | --- |
| Premiere Generative Media Tool | 用专门工具拖选时间范围，弹出生成工具条，输入提示词、选模型与参考帧，结果进入时间线 | 编辑位置和目标时长成为生成上下文 |
| Premiere Generative Extend | 拖动已有素材的入点或出点，生成延长部分 | 已有片段的延展入口，应与新建镜头区分 |
| ChatCut | Agent 可生成并安排片段；手动 Video Gen 流程在生成面板设参数，结果先进入 My Assets，再拖到时间线 | 自然语言编排与手动参数配置共用素材结果 |
| Firefly video editor（beta） | 编辑器内生成面板；可用播放头当前帧作首帧/尾帧，结果进入生成历史后拖入时间线 | 从正在编辑的项目取参考帧，保留生成历史 |
| CapCut Desktop | 官方说明从左侧 AI media 进入文生/图生视频，选择模型、时长和比例 | 生成模型的设置入口清晰；本次资料没有证实“空白轨道直接画生成片段” |

对应来源：[Premiere 生成步骤](https://helpx.adobe.com/premiere/desktop/edit-projects/edit-with-generative-ai/generate-media-with-generative-media-tool.html)、[Generative Extend](https://www.adobe.com/learn/premiere-pro/web/add-frames-generative-extend)、[ChatCut 手动工作流](https://chatcut.io/docs/video-generation-models)、[ChatCut Agent 生成示例](https://chatcut.io/features/ai-video-generator)、[Firefly 编辑器](https://helpx.adobe.com/firefly/web/firefly-video-editor/generate-videos/generate-video-using-firefly-models.html)、[CapCut Desktop](https://www.capcut.com/tools/ai-video)。

### Premiere 的具体交互

官方教程确认拖选范围后再设置提示词、模型、参考帧和模型允许的参数，并在生成前展示积分估算。首尾帧可用于连接镜头，支持的模型还能生成配套音频。[操作文档](https://helpx.adobe.com/premiere/desktop/edit-projects/edit-with-generative-ai/generate-media-with-generative-media-tool.html)

官方首发说明还展示了双击轨道空隙选定范围，以及在其他任务生成时继续创建范围、从多个生成版本中选择结果的交互。[官方演示与说明](https://community.adobe.com/questions-734/now-in-beta-generate-sound-effects-and-video-in-the-premiere-timeline-1632259)

这里要区分四种意图：

- **新建**：在目标位置生成新的镜头。
- **延展**：续接已有片段的开头或结尾，需要模型支持。
- **桥接**：指定前后参考帧，生成连接它们的片段；模型输出连续性仍需检查。
- **改写**：用已有视频作输入生成新版本，同时保留原素材。

同样的时间线入口可以承接这些意图，但不能把“不支持视频延展的图生视频模型”包装成真正的原片延展。

## Velocut 当前已经具备的部分

以下为源码核查结论，并非对真实供应商接口的实测：

| 已有基础 | 当前实现 |
| --- | --- |
| 可配置渠道与模型 | 浏览器配置保存 channel、provider kind、base URL、key、model IDs |
| 异步视频生成适配器 | `TaskApiVideoGen` 提交任务后轮询，支持状态回调和 AbortSignal |
| 生成输入 | prompt、duration、ratio、resolution、音频开关、首尾帧、参考图/视频 |
| 媒体参考 | `uploadFrame/uploadClip` 等返回受控引用句柄 |
| 结果下载与落轨 | 下载结果、保存媒体、probe、注册 asset，按 `trackId/atUs` 插入；默认追加到 Generated 轨道 |
| 时间线交互 | 已有时间坐标换算、吸附、拖动/裁剪手势和素材拖入占位预览 |
| 原子资源工作流 | 已有 resource import、media.probe、registerAsset、addClip 等基础 |

源码：[生成适配器](../../web/packages/render-sdk/src/videogen.ts)、[生成与落轨服务](../../web/apps/editor/src/services/videogen.ts)、[时间线](../../web/apps/editor/src/ui/TimelinePanel.tsx)、[资源任务](../../web/packages/runtime/src/resource-jobs.ts)。

尚需补齐的关键环节：

1. 时间线空白处目前执行播放头拖动，没有“生成范围”手势或持久化生成占位。
2. 渠道发现仅提供模型名称，缺少每个模型的输入类型、时长档位、比例、分辨率、音频、续写与取消能力描述。
3. 现有适配器把 `durationS` 四舍五入后发送；落轨直接采用 probe 后的实际素材时长，没有协调目标范围与生成时长。
4. `generate()` 将提交和轮询封在一次长调用中，taskId 主要在成功结果中返回，缺少可恢复的任务回执。
5. 现有资源 jobs 以运行期内存为生命周期，而且只开放 `media.probe` 等任务，不能直接等同于持久化视频生成队列。
6. `generateVideoClip` 的建轨、注册素材、放置片段是分次 dispatch；最终落轨冲突时，前面的变更可能已经发生。
7. 生成结束后才读取全局 `activeStorage()`。持久任务需要从提交时就固定目标项目和存储，避免等待过程中切换项目产生错配。

## 建议的第一版体验

### 创建入口

增加显式的“生成”工具。该模式下在视频轨道空白位置拖出范围，松手即出现生成占位和设置面板；普通选择模式继续保持原有点击/拖动行为，避免手势冲突。

同时提供双击空隙、右键“在此生成”和输入开始时间/时长的替代入口。在 Codex 小窗里不把精确拖动作为唯一方式。

例如在 V2 的 00:12–00:18 画出一个 6 秒范围：

```text
V2  ─────────── [ 生成镜头 · 00:12—00:18 · 草稿 ] ───────────
V1  [ 原始镜头 A             ][ 原始镜头 B                  ]
A1  [                         音乐                         ]
```

设置面板只放必要输入：提示词、渠道/模型、目标时长、比例、参考帧、生成按钮；分辨率、seed 等参数折叠。选用模型后动态展示其支持的字段，明确列出会上传的参考画面。费用有可靠估算时显示；无法估算时显示供应商计费，不能虚构金额。

参考帧可以选素材、当前帧、前一片段末帧或后一片段首帧。需要区分“单片段原帧”和“合成画面”，避免把字幕或其他轨道内容意外带进参考图。每次提交保存不可变参考快照，后续编辑不会改写正在进行的请求。

### 生成与采用

占位片段显示草稿、排队、生成中、下载中、待采用、失败等状态。用户可以继续编辑其他位置。

生成完成后，在占位位置预览候选；采用某一候选时，注册素材与放置/换源作为一次原子提交。多次生成保留为独立候选，切换候选沿用稳定的剪辑身份和已有变换、效果等编辑信息。

空白范围首次生成可以提供“完成后自动采用”的明确选项；已有片段改写默认先预览候选。自动采用只在占位身份和内容版本仍匹配时进行。

### 时间与并发规则

- 保存目标时长、供应商请求时长、实际素材时长三个值。
- 例：假设某模型只支持 5/10 秒，用户选择 6 秒，则明确显示“生成 10 秒，采用其中 6 秒”。这是适配策略示例，不指代某个实际模型的固定规格。
- 结果过长可以裁切并保留完整源素材；结果过短需要选择调整范围或重新生成。变速应是显式编辑操作。
- 生成过程中，占位被移动可以在兼容且用户意图清晰时沿用新位置；占位被删除、改长、改提示词或被其他片段占据，则结果进入素材/候选区，不自动覆盖。
- 原子采用检查当前 revision、slot ID 和 slot 内容版本。它不必要求整份文档保持生成开始时的 revision，否则用户编辑别处也会使所有任务失效。
- 撤销采用只撤销剪辑变更；重做使用已有结果，不重新付费提交生成。
- 取消本地等待与供应商确认取消需要分别记录。超时、断网或关闭窗口后优先恢复轮询已有 providerTaskId，避免重复提交。
- 重试新的生成是一个新任务，有新的 requestId，并关联前一任务；接口级重试则复用原幂等标识。
- 结果及时持久化到提交时绑定的项目存储；不把长效项目资产指向会过期的下载 URL。
- 未完成的生成占位不能伪装成已完成视频。导出前明确列出未解决范围，避免无声地输出空白或占位图。

## 下层仍采用原子能力

下列名称是拟议接口，不表示已经实现：

| 原子职责 | 建议接口方向 | 边界 |
| --- | --- | --- |
| 查询模型能力 | `generation.capabilities` | 返回输入 schema、规格及取消/续写支持 |
| 管理生成占位 | `generationSlot.create/update/remove` | 只管理目标轨道、范围与生成意图；不调用外部 API |
| 捕获参考 | 复用/扩展帧提取和上传能力 | 返回不可变、项目绑定的引用 |
| 管理生成任务 | `generation.submit/get/list/cancel` | 提交后立即返回持久任务 ID；不自动剪辑 |
| 持久化结果 | 复用 resource import/probe | 结果可独立存在于素材区 |
| 注册素材 | 复用 `registerAsset` | 不隐式插入时间线 |
| 采用或换候选 | 单片段换源/占位完成操作 | 与注册素材组合成一个事务，保持剪辑身份 |

UI 可以把上述步骤组合为顺畅的“画范围 → 生成 → 采用”；Agent 则能够自己选择参考、提交多个任务、比较候选并决定落轨。旧的 `videoGen()` 可作为兼容编排入口，但新能力不应继续只暴露这一整个流程。

任务记录与剪辑历史要分开：提示词与占位属于可撤销编辑意图，供应商任务回执/进度/结果属于持久执行记录。撤销不会抹掉已经发生的远端任务。

## 实施顺序与验收

第一轮做空白范围生成、模型能力描述、持久任务回执和原子落轨，支持文生视频及首帧图生视频。之后增加首尾帧桥接、候选切换，再按供应商能力开放视频改写/延展；音效与音乐可复用这条时间范围工作流。

验收至少包含：

1. 选择 6 秒范围，模拟供应商返回更长/更短素材，落轨行为与界面说明一致。
2. 两个任务乱序完成，分别回到正确占位，且只提交一次。
3. 生成过程中移动/删除占位、编辑其他片段、切换项目，结果不会覆盖错误目标。
4. 重载可恢复排队/生成中任务；轮询重试不会再次提交生成。
5. 失败、取消、结果下载失败均保留可追踪回执和重试入口。
6. 采用、换候选、撤销、重做都保持剪辑编辑信息，并且不触发重复生成。
7. 小窗使用数字输入和面板也能完成全流程。
8. 用 mock provider 完成自动回归，再按用户配置和明确生成操作做实际供应商联调。

供应商价格、模型名单与规格会变化，采用 provider capability 数据而不是在时间线组件中硬编码。主要工程量在任务恢复、时间规格适配和并发落轨一致性；范围绘制可以复用现有时间线坐标与吸附能力。
